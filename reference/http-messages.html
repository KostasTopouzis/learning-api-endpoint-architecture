HTTP message cheat sheet

One request in, one response out. Four parts each.

Request

POST /api/orders HTTP/1.1      ← request line: method target version
Host: the-edit.vercel.app      ← headers: Name: value
Content-Type: application/json
↵                              ← empty line: head ends
{"items":[…]}                  ← body (POST/PUT/PATCH)

Response

HTTP/1.1 201 Created           ← status line: version code reason
Content-Type: application/json ← headers
Location: /api/orders/ord_789
↵                              ← empty line
{"id":"ord_789",…}             ← body (optional)

Rules of thumb

  • The client always initiates; the server only ever responds.
  • The request target is only the path; the domain goes in the Host header.
  • Header names are case-insensitive; each header is one line.
  • GET has no body. POST, PUT, PATCH carry one.
  • The reason phrase is decoration. Code reads the status number.
  • Stateless: every request must carry its own context (cookie / token header).
  • HTTP/2 & 3: binary frames; start line becomes :method, :path, :status. Same parts.
